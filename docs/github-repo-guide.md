# GitHub Repository Guide

One section per repository this team works in, keyed by its GitHub `owner/repo`.
The Status MCP (`ai/mcp/StatusMcp/server.py`) reads this file on every
`get_project_status()` call: for each checkout under the project root it matches
`remote.origin.url` to a section here and shows that section's **Critical**
bullets directly in the status output, with a pointer back to this file for the
rest. A fresh session therefore sees the critical facts about the checkouts in
front of it without reading anything, and only opens this file for detail.

## How this file is read

- `## Owner/Repo` - one heading per repository, matched case-insensitively
  against the GitHub owner/repo parsed from the remote. `## Every repository`
  applies to all of them and is shown as top-level `guidance`.
- `- **Default location**: <root>/name` - where the scripts assume this repo is
  when they are not told otherwise. A checkout anywhere else gets a `warning`
  in the status output naming the `-SourceRoot` it needs. Optional.
- `### Critical` - bullets shown verbatim every session. Keep them short and
  keep them few; this is the part that is always in front of the model.
- `### Notes` - everything else. Read on demand.
- Placeholders in bullets: `{ai}` is the `ai/` folder, `{root}` is the checkout
  being described, `{projectRoot}` is the folder holding all checkouts. They are
  expanded with forward slashes, which is how `pwsh -File` is invoked from the
  Bash tool.

## Every repository

### Critical

- Every build, test and run goes through the scripts under `{ai}/scripts/<project>`. If a script lacks the switch you need, add the switch; never write a one-off runner in `{ai}/.tmp` that only this session knows about.
- Before writing any script, list `{ai}/scripts/<project>` and read its README - the canonical runner usually already exists.
- More than one checkout of a repo can sit under `{projectRoot}`. Scripts build the default location when `-SourceRoot` is omitted, and a build against the wrong checkout succeeds in seconds and looks real. Use the build/test lines given for the checkout verbatim.

### Notes

- Sibling checkouts of pwiz are near-identical, so never search across all of
  them; scope every search to the active checkout (see the root CLAUDE.md).
- The reuse rule exists because session-local scripts in `ai/.tmp` are lost
  with the session, while a switch added to the canonical script is found by
  the next one. See `ai/scripts/README.md` for the index.
- A `ai/.tmp/run-*.ps1` script named in a handoff is a symptom, not a template:
  it is usually a previous session's shortcut past a runner that already exists
  (e.g. `ai/scripts/Osprey/SEA-AD/Run-SeaAd.ps1` was rewritten from a `.tmp`
  copy once, at the cost of ~70 minutes and ~340 GB of needless cache rewrites
  the canonical script already avoided).

## ProteoWizard/pwiz

- **Default location**: `{projectRoot}/pwiz`

### Critical

- Skills: `skyline-development` (Skyline, `pwiz_tools/Skyline`), `osprey-development` (C# port, `pwiz_tools/Osprey`), `version-control` before any commit or PR.
- Build: `pwsh -File {ai}/scripts/Skyline/Build-Skyline.ps1 -SourceRoot {root}`
- Test: `pwsh -File {ai}/scripts/Skyline/Run-Tests.ps1 -SourceRoot {root} -TestName <Name>`
- Scripts: `{ai}/scripts/Skyline` (README.md, PRE-COMMIT.md), `{ai}/scripts/PwizSharp`, `{ai}/scripts/AutoQC`, `{ai}/scripts/SkylineBatch`, `{ai}/scripts/Osprey` (`Build-Osprey.ps1 -SourceRoot {root}` builds the C# port).

### Notes

- `Build-Skyline.ps1` detects the SDK-style (`net10.0-windows`) tree from
  `Skyline.csproj` and shells out to `dotnet`; a net472 tree goes through
  MSBuild. Either way the target checkout is printed on the first lines -
  check it.
- Branches are `Skyline/work/YYYYMMDD_feature`; PR titles carry the module
  prefix (`skyline:`, `pwiz:`, `osprey:`) and the matching label. Details in
  `ai/docs/version-control-guide.md`.
- Tests are run by `TestRunner.exe` from `bin/staging/<Config>`; the
  `Deny-DirectBuildTest.ps1` hook blocks direct invocation, so use the scripts.
- Perf and tutorial tests need datasets downloaded into the machine's test
  data area; see `ai/docs/build-and-test-guide.md`.

## ProteoWizard/pwiz-ai

- **Default location**: `{projectRoot}/ai`

### Critical

- This is the `ai/` folder: docs, skills, commands, scripts, TODOs. Commit directly to master; update with `git pull --rebase`, never a merge commit.
- Skill: `ai-context-documentation` when editing anything here. Script index: `{ai}/scripts/README.md`.

### Notes

- `ai/root-CLAUDE.md` is hard-linked to `<projectRoot>/CLAUDE.md` by the Status
  MCP, so edits at either path are the same file.
- `ai/TOC.md` is generated by `ai/scripts/Generate-TOC.ps1`; regenerate it after
  adding a doc.

## maccoss/osprey

- **Default location**: `{projectRoot}/osprey`

### Critical

- Rust Osprey. Skill: `osprey-development`. Guide: `{ai}/docs/osprey-development-guide.md`.
- Scripts: `{ai}/scripts/Osprey` (`Run-Osprey.ps1`, `Test-Snapshot.ps1`, `Dataset-Config.ps1`); the tree is resolved by `Get-OspreyRoot` in `Dataset-Config.ps1`, not by `-SourceRoot`.

### Notes

- The C# port (OspreySharp) lives in `ProteoWizard/pwiz` under
  `pwiz_tools/Osprey`; parity work touches both repos.
- PRs go to `maccoss/osprey` (`gh pr create --repo maccoss/osprey`). Skyline's
  C# conventions do not apply here.
- Large-dataset layout and diagnostics: `ai/docs/osprey-run-layout.md`,
  `ai/docs/osprey-large-datasets.md`, `ai/scripts/Osprey/DIAGNOSTICS.md`.
