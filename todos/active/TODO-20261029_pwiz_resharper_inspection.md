## Objective

Extend the ReSharper code inspection that gates Skyline.sln to the ported C# in Pwiz.sln
(pwiz core, vendor readers, BiblioSpec, msconvert, MSConvertGUI, SeeMS, MsDiff, ...), with
the same rules except where ported code legitimately differs - first of all localization,
which SeeMS, MSConvertGUI and the command-line tools do not do.

## Findings so far (2026-10-29)

Measured with `dotnet jb inspectcode Pwiz.sln --no-swea -e=WARNING` (the tool pinned in
`pwiz_tools/Skyline/.config/dotnet-tools.json`, 2025.3.3), run from `pwiz_tools/Skyline`.
About 3-4 minutes on a built tree.

- **Baseline with Skyline's rules** (`--profile=Skyline.sln.DotSettings`): 4407 findings.
  SeeMS 2461 (1702 of them `TabsAreDisallowed`), Analysis 363, MsData 274, MsConvertGUI 184,
  everything else under 100. By type: tabs 1702, `RedundantNameQualifier` 864,
  `RedundantUsingDirective` 530, `CheckNamespace` 261, `LocalizableElement` 130, ~150
  nullable-contract warnings, 67 `EmptyGeneralCatchClause`, 5 CS0162 reported as ERROR
  (`SpectrumList_ChargeFromIsotope.cs`, `MSFReader.cs`).
- **The 7 projects shared with Skyline.sln** (ZedGraph, MSGraph, CommonUtil, CommonMsData,
  CommonBaseUI, CommonFileDialogs, ProteowizardWrapper) show 0 under Skyline's rules and 2536
  under ReSharper defaults. Pwiz.sln must keep Skyline's rules or exclude them, or the two gates
  disagree about the same code.
- **LocalizableElement fires without any opt-in**: ReSharper's default localizability treats
  WinForms forms (and some exception messages) as localizable. Fixed by `Localizable=No` at the
  solution layer; projects opt in with a `*.csproj.DotSettings` `Localizable=Yes`, as CommonUtil,
  CommonMsData and MSGraph already do. (SkylineBatch/AutoQC solve the same problem differently:
  `Sync-DotSettings.ps1` demotes `LocalizableElement` to HINT.)
- **Settings-layer injection does not work in inspectcode.** A `Pwiz.sln.DotSettings` holding
  only a `FileInjectedLayer` pointing at `Skyline.sln.DotSettings` was ignored, with
  `RelativePath` alone and with `AbsolutePath` added - the run fell back to defaults (2160
  `InconsistentNaming`, no `TabsAreDisallowed`). So the settings are a copy.
- **Roslyn CodeStyle analyzers fail to load** in inspectcode (`Microsoft.Bcl.AsyncInterfaces
  10.0.0.1` not found). Findings from those analyzers may be missing; check whether Skyline's
  CI run shows the same.

## Policy (decided 2026-10-29)

The pwiz-side gate looks for **code that may be wrong, not for tidiness**. Skyline's checks can be
stricter; pwiz must not get a giant change set. So:
- `Pwiz.sln.DotSettings` = Skyline's settings + `Localizable=No` + 44 style/redundancy inspections
  hidden (tabs, redundant qualifiers/casts/usings/etc., namespace-folder match, XML doc,
  nullable-contract "never null" hints, unused private members). `InconsistentNaming` stays a
  HINT as in Skyline's settings: visible in the IDE, outside the gate. Generated by
  `ai/scripts/Skyline/scripts/Sync-DotSettings.ps1` (Pwiz target, `$pwizHiddenInspections`).
- Unused usings stay. No qualifier, whitespace, or namespace changes.
- What remains (~206) is bug-risk: empty general catches (67), bitwise ops on non-[Flags] enums
  (24), culture-sensitive string ops (24), virtual calls in constructors (13), always-true/false
  conditions and unreachable code (24), member hiding (14), using/dispose misuse (17), multiple
  enumeration (10), and singletons (division by zero, format string, inconsistent locking, ...).

### Rejected along the way (do not retry)
- `jb cleanupcode` (optimize usings + shorten references + remove redundancies): shortened
  qualifiers nobody flagged (e.g. `System.Globalization.CultureInfo` + new using), broke the
  no-vendor build (vendor-only usings hoisted above `#if !NO_VENDOR_SUPPORT`, using needed only
  in a `#if NO_COMPASSXTRACT` branch removed), corrupted Latin-1 `RBTree.cs`, and touched
  `ProteowizardWrapper.PwizSharp` despite the exclude.
- Applying flagged-only fixes from the inspection XML (offsets), intersected across vendor and
  no-vendor reports: correct mechanically, but still churn, and ReSharper falsely flagged
  `using System.ComponentModel` in SeeMS `ProcessingListView.cs` (needed for `IContainer`).
- Tab expansion in SeeMS, per-project `CheckNamespace` off, `RootNamespace` on test csprojs.

### Facts worth keeping
- No-vendor full `Pwiz.sln` does not build on master (`ThermoModelParityTests.cs` CS0117,
  `SeeMS/Processing.cs` CS0246). CI's no-license build targets `MsConvert.csproj` only, which
  builds. Use `--no-build` to inspect the no-vendor configuration.
- The `ProteowizardWrapper` sources live in `pwiz_tools/Shared/ProteowizardWrapper.PwizSharp`
  (linked into ProteowizardWrapper.csproj) - a CI exclude must name that folder.
- **Vendor readers must not warn through `Trace`.** Skyline listens: SkylineCmd's
  `TraceWarningListener` writes warnings into command output, and the UI's
  `ImmediateWindowWarningListener` opens the Immediate Window. Use
  `SpectrumListBase.WarnOnce` (stderr, deduplicated by message text, so the text must not
  vary per scan) or `Console.Error` in classes that are not spectrum lists.
- **What no gate inspects** (C# projects in neither Pwiz.sln nor Skyline.sln): CarafeSharp
  (own .sln), Osprey (own .sln), `build/AgilentPatcher`, `build/VendorPinsGenerator`,
  `ProteowizardWrapper.PwizSharp.Smoke`, `BindingRedirectGenerator`. ProteomeDb,
  PanoramaClient, BiblioSpecUtil and `Shared/Common/Common.csproj` are in Skyline.sln.
  A stray net472 `Shared/Common/CommonUtil.csproj` (from #2495, referenced by nothing, could
  not build) was deleted in 5a4121da6a.
