Summary

Osprey has one output path (a CommandStatusWriter behind OspreyOutput.Out), so every line can be traced to a call site. There are 583 emitting call sites outside the tests, counted on master at 794cb6a5d8 (PR #4646, which retired --input-scores) as merged into this branch. Only the first tier below reaches a user who runs Osprey with no diagnostic flags.

399 default log (every run)
83 --perf-stats [COUNT] [TIMING] [BENCH] [STAGE-WALL]
35 --model-diagnostics
31 -d / OSPREY_DUMP_* bisection dumps
20 --verbose
12 --fdrbench / entrapment
3 OSPREY_LOG_MEMORY

The gating itself is in good shape: timing, count, memory and bisection lines are already kept out of the default log. The problem is inside the default tier. Of its 399 lines, 47 contain a C# method, class, task or variable name, 53 say "sidecar", 15 name an OSPREY_* environment variable, and roughly 120 use at least one term that exists only inside the codebase (compaction, survivors, hydrate, stratum, base_id, fold, bundle, stubs, projection). Two of the worst lines print in every default run, and one of them announces the default second-pass mode by its environment-variable name.

This page is the developing spec. Brendan's term-level decisions from the CSV review of 2026-09-09 are applied to the glossary and to the rewrites below; the glossary's Decision column marks the terms still open. On 2026-09-11 the scope widened: the user-facing text moves to RESX files in the same sprint, so Osprey can be translated with Skyline's pipeline. The implementation spec, including the RESX mechanics and the inventory of every script and test that reads log text, is ai/todos/backlog/brendanx67/TODO-osprey_log_readability.md.

Two findings from the real logs. In the 82-file SEA-AD run, 82 of the 369 log lines are the same developer note repeated once per file ("Loaded N FDR stubs (features not loaded - not read on this path)"). In the Stellar run, the first-pass FDR section opens with a method name: "[PATH] First-pass streaming ingest (RunStreamingFirstPass): 1448698 rows".

A · User-facing lines, by likelihood of confusion

Lines a researcher sees in an ordinary run (no --verbose, --perf-stats, -d or environment variables). High means the line prints in every default run and uses vocabulary the reader cannot map to anything they know, or identifies itself by a code or environment-variable name. Medium means the reader can guess, but the phrasing is internal or reads like a code comment. Low means resume, error or HPC-task paths, or a mild wording issue. Jargon is marked; a suggested rewrite follows each line. Paths are checkout-relative under pwiz_tools/Osprey.

What to change

  1. Gate before rewriting. Moving the B1 lines behind --verbose or OSPREY_LOG_MEMORY removes about a third of the default-tier jargon with no wording decisions. It also cuts the 82-file log by roughly a quarter. Add [PATH] and [TRAIN] to OspreyOutput.IsStatLine so the regression gate keeps its assertions under --perf-stats.
  2. Rewrite the thirteen High rows. A1, A2 and A11 are the ones a new user hits in the first run that reaches the second pass; A3, A4, A5 are in every run. Use the glossary's right-hand column as the rename map so the same internal word always becomes the same plain phrase. Where the word names a data structure (stratum, retained set, survivor pool, projection), a one-word substitute is not enough: the rewrite must state the effect on the results, such as which precursors get new q-values and which keep their first-pass values.
  3. Move the user-facing text to RESX in the same sprint (decided 2026-09-11). Every default-tier and --verbose line, the --help text and the user-correctable exception messages become resources, one Resources.resx per assembly that emits user prose. Machine-channel and diagnostic strings stay verbatim @"...", which is Skyline's exemption marker. Enforcement is Skyline's: a .csproj.DotSettings per project with Localizable = Yes and LocalizableInspector = Pessimistic turns the existing zero-warning inspection gate into the RESX gate. The translation pipeline needs no change; it already sweeps all of pwiz_tools. Full mechanics in the backlog TODO.
  4. Fix the three enum leaks in the banner (A13) with Skyline's GetLocalizedString extension pattern over the same resource strings.
  5. Leave the [TASK] section markers alone (A14, decided). Their names are the --task values from the command-line help, and ai/scripts/perfviz.py and regression.ps1 depend on the exact text.
  6. Trim the Table C warnings to the user sentence each already contains, and move mechanism, issue numbers and method names into code comments beside the call.
  7. Adopt three rules for new lines, checkable in review: no C# identifier, task name or environment variable appears in a default-tier line unless the user typed it; no "Stage N" at all, only the --task names the help documents; every count carries a thousands separator; "detections" is the word for candidates that passed the current cutoff; and a line that only records what the code no longer does or how memory is managed (frozen model, no retrain, resident, byproduct, interned) is diagnostic output behind --verbose, --perf-stats or OSPREY_LOG_MEMORY, never user text.

Method: every emitting call site under pwiz_tools/Osprey (excluding Osprey.Test) was extracted mechanically, 582 in all, then classified by the flag that exposes it using the gates in OspreyOutput.cs, PipelineContext.LogVerbose, ProfilerHooks.MemoryLoggingEnabled and the diagnostics sinks. Term counts are regular-expression matches over the default tier. Priorities are judged against the two evidence logs named in the header; example numbers in the rewrites are taken from those logs.
