Osprey one-command workflows

The three ways one Osprey command goes from a protein FASTA and DIA runs to a .blib for Skyline, drawn as the Osprey and CarafeSharp workflow pages are: one column per mode, one box per phase, the file each phase leaves for the next named on the arrow. Purple boxes are CarafeSharp's tasks, run in-process through the shared pipeline driver; red boxes are Osprey's own four-stage analysis. Today's search with a given library (-l library.blib, "mode 0") is the red box alone and does not change. The design is TODO-osprey_one_command.md beside this file.

The phases and their checkpoints. Every phase is a task on the shared pipeline contract (PipelineTask in CommonUtil) with a validity key over its settings and inputs, so a resumed command skips every phase whose output is current: a change to a digest option re-runs everything, a change to --training-input re-runs the tuning search and after, a change to -i alone re-runs only the final search.

What the user gets (--output-dir and --work-dir relocate it as they relocate today's sidecars):

out.blib                       the result (-o), sidecars as today
out.library.blib               the library it was searched with (modes 1-3); -l takes it next time
out.carafemodel                the tuned model (mode 2); --model takes it next time; CarafeSharp --model_info describes it
out.library/                   working files of the library build - one folder a user can delete
  peptides.fasta, pairing.tsv                      digest (the final library)
  training-peptides.fasta, training-pairing.tsv    only with --entrapment
  initial.blib                                     the training library (mode 2)
  training/                                        the training analysis: parquets, sidecars, the exports, training.blib
  model/                                           Carafe's model folder (what --model_dir reads)

Against DIA-NN. --fasta with no -l is DIA-NN's --fasta --gen-spec-lib --predictor; -i is --f; out.library.blib is --out-lib; the digest and modification options are CarafeSharp's (--enzyme, --miss_c, --min_pep_len, --fixed_mod, --var_mod, ...) surfaced as sections of Osprey's help, where DIA-NN has --cut, --missed-cleavages, --min-pep-len, --unimod4, --var-mods. Mode 2 has no DIA-NN counterpart: its --reanalyse builds an empirical library from a first pass and never adapts the predictor. Mode 3 is what makes mode 2 reusable: tune once per instrument and method, predict any proteome with the saved model after that.
