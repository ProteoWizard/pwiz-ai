Progressive disclosure

The new rows are hidden, not greyed. Unchecked, the panel is identical to today's — not a quieter version of a busier form, the same form. Checking the box reveals the source and ratio; choosing a FASTA source reveals the file row. Three states, each showing only what applies.

Implementation

GridBagLayout skips invisible components, so setVisible(false) collapses each row rather than leaving a gap — state 1 is the current layout exactly, not an approximation of it. Toggling calls revalidate() then repaint() on the panel; the tab already sits in a scroll pane, so nothing below needs repositioning by hand.

The hazard this paradigm introduces

A hidden field keeps its value. If someone picks a FASTA, switches the source back to Shuffle, and runs, the path is still in the model — and a command builder that asks “is the FASTA field non-empty?” will silently pass -entrapment_db and build a foreign-entrapment library the user did not ask for.

So buildEntrapmentFastaCommand keys off the logical state, not the field contents: emit -entrapment_db only when the checkbox is on and the source combo reads FASTA. Same for -entrapment_ratio, which is emitted only when entrapment is on and the value is not 1.00. Values are still persisted, so the path survives a round trip — it just does not reach the command line while hidden.

Reuses what is already there

Browse is createBrowseButton with a fasta / fa / fasta.gz filter. Download opens the existing UniProtDownloadDialog, which already offers human, mouse, yeast, E. coli and Arabidopsis thaliana (UP000006548) — the proteome this feature was built and measured against. The same Browse + Download pairing sits beside Train and Library Protein Database on the Workflow tab, so the row needs no new vocabulary.

Validation

Two checks, both before the run starts rather than partway through a multi-hour build.

  • Source = FASTA with no file. Block Run and focus the field: “Select an entrapment FASTA, or set Entrapment source back to Shuffle target sequence.”
  • Ratio below 0.10. Unreachable from the spinner, which is bounded — but Carafe enforces it anyway, because Carafe additional options can pass the flag directly:
-entrapment_ratio 0.0500 is below the tested minimum of 0.10. Ratios down to 0.10 are characterised - the combined FDP estimate is stable across r = 1, 0.5, 0.25 and 0.1 - but at 0.10 only ~32 entrapment peptides were accepted at 1% q, so below it the estimate is dominated by counting noise and has not been validated. If you have a case that needs a lower ratio, raise it so the bound can be widened deliberately.

The bound lives in Carafe, not in the panel. One place to widen it when someone makes the case, and the spinner range simply reflects it.

Deliberately not exposed

BehaviourWhy it stays off the panel
Fragment-overlap
similarity gate		 Always on, no flag. It is a correctness fix, not a preference — a library built without it carries entrapment peptides that are near-copies of their own targets.
I/L collision
rejection		 Always on, no flag. Same reasoning, and it matters most exactly when someone uses the new FASTA source: conserved plant/human proteins yield tryptic peptides differing only by I↔L, which are mass-identical to a real target and detected wherever it is.
-no_similarity_gate CLI only. It reproduces pre-gate behaviour for audit comparison and produces a library that should not be searched. Putting it on a settings panel invites exactly the use it must not have.

Notes

  • The panel has no button column today, so the Browse/Download row widens the layout slightly when it appears. That is why the FASTA row is the only new row carrying buttons — the source and ratio rows stay inside the existing two-column grid.
  • Switching source back to Shuffle collapses the FASTA row but keeps the path, so toggling between the two arms of an A/B does not mean re-picking the file each time.
  • Nothing here changes what a run does when entrapment is off. Unchecked, the emitted command is byte-identical to today's.
